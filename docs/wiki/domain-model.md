# Domain Model

The "domain" here is tiny: there are no runtime entities — only identifiers
that travel through the build, the registry, and the fanout payload.

## Identifiers

### `ALPINE_VERSION`

- **Type:** string.
- **Format:** `<MAJOR>.<MINOR>.<PATCH>` (Alpine release version).
- **Example:** `3.24.1`.
- **Authoritative source:** the first entry of `latest-releases.yaml` fetched
  from `dl-cdn.alpinelinux.org`.
- **Used as:** image tag `:ALPINE_VERSION`; submodule checkout reference via
  `v<ALPINE_SHORT_VERSION>`; value of `tag` in the fanout payload.

### `ALPINE_SHORT_VERSION`

- **Type:** string.
- **Format:** `<MAJOR>.<MINOR>`.
- **Example:** `3.24`.
- **Derived:** `cut -d. -f1-2 ALPINE_VERSION`.
- **Used as:** part of `ALPINE_LOCAL_VERSION` prefix; submodule tag pin.

### `ALPINE_LOCAL_VERSION`

- **Type:** string.
- **Format:** `<ALPINE_SHORT_VERSION>.<UTC-ISO8601>` with `:` replaced by `-`
  (so it is filesystem- and tag-safe).
- **Example:** `3.19.2024-01-27T04-39-33`.
- **Generated by:** `echo $(alpine_short_version).$(DATE) > ALPINE_LOCAL_VERSION`
  in the `build` target, where `DATE = $(shell date -u +%Y-%m-%dT%H-%M-%S)`.
- **Used as:** image tag `:ALPINE_LOCAL_VERSION`; value of `local_tag` in the
  fanout payload.

### `YQ_VERSION`

- **Type:** semver string.
- **Format:** `<MAJOR>.<MINOR>.<PATCH>`.
- **Example:** `3.3.4`.
- **Used as:** image tag for the `mikefarah/yq` container in `Makefile.update`.

## Image tags (in the registry)

| Tag | Set when | Pushed by |
| --- | --- | --- |
| `registry.digitalocean.com/cwimmer/alpine:intermediate` | Every `make build` (local only) | **Not pushed** by Makefile |
| `registry.digitalocean.com/cwimmer/alpine:<ALPINE_VERSION>` | Whenever the published image is built | `make upload` |
| `registry.digitalocean.com/cwimmer/alpine:<ALPINE_LOCAL_VERSION>` | Every `make build` | `make upload` |

## Fanout payload

```json
{
  "event_type": "base-image-updated",
  "client_payload": {
    "image": "registry.digitalocean.com/cwimmer/alpine",
    "tag": "<ALPINE_VERSION>",
    "local_tag": "<ALPINE_LOCAL_VERSION>"
  }
}
```

Consumers are expected to consume `client_payload.image`, `.tag`, and
`.local_tag` and rebuild themselves.

## Submodule pointer

- `docker-alpine/` is a git submodule (declared in `.gitmodules`) whose
  pointer is tracked like any file. Updates land via
  `git submodule update --init --recursive` followed by `git checkout` to
  `v<ALPINE_SHORT_VERSION>`. The new pointer is committed by
  `commit-updates` / `commit-updates-pipeline`.

## Source map
- `ALPINE_VERSION`, `ALPINE_SHORT_VERSION`, `ALPINE_LOCAL_VERSION`, `YQ_VERSION` — identifier files
- `Makefile` — `build` and `upload` tag construction
- `Makefile.update` — `ALPINE_VERSION` / `ALPINE_SHORT_VERSION` derivation
- `.github/workflows/publish.yml` — fanout payload construction
- `.gitmodules` — submodule binding

## Confidence / gaps
- Solid: identifier formats and where each is generated, consumed, and
  transmitted.
- Uncertain / to verify: the `ALPINE_LOCAL_VERSION` in the working tree
  (`3.19.2024-01-27T04-39-33`) does not match the current `ALPINE_SHORT_VERSION`
  (`3.24`). This is stale state — the local-version file is meant to be
  regenerated on every build, and the on-disk value is left over from an
  earlier short-version pin. See [open-questions](open-questions.md).
